# ExpEvo — experiment artifacts and reproduction package

Everything behind the experiments in the IEEE TMC submission: the code, the raw and intermediate data
produced by the runs, the logs, and the scripts that turn them into the paper's tables and figures.

**All tables and figures can be regenerated from the shipped data with one command and no network
access:**

```bash
./run_all.sh          # ~10 s, no LLM calls, no root, no network
./verify.sh           # checks the regenerated numbers against the values used in the paper
```

`run_all.sh` does **not** re-run any LLM inference. The expensive stages (interaction, distillation,
condensation, held-out answering) are already done and their outputs are shipped; every figure and
table is a deterministic function of those outputs.

### The three experiments

| Paper item | Question | Data that backs it | Regenerated by |
|---|---|---|---|
| **Fig. 5**, §V-C | how many bytes move across the experience lifecycle? | 24,000 measured episodes + 24,000 distilled experiences + 4 refined repositories | `src/metrics.py`, `src/plots_paper.py` |
| **Fig. 6**, §V-C | what does payload reduction do to upload latency when clients share a link? | the same 24,000 payload pairs, replayed through an FCFS queue simulation | `fig6_network_simulation/src/*` |
| **Fig. 7 + Table II**, §V-D | does backend refinement cut storage/entries without hurting accuracy? | 16 refined repositories, 11,000 held-out answers | `runs/p10_backend_refinement/scripts/*` |

A sixth experiment (`runs/tsc_backend_overhead/`) measures the backend management overhead of
refinement on High School Geography: the one-off local cost of building the similarity matrix and the
anchor groups, the historical LLM condensation requests, and the per-query BM25 latency of the full
6,000-entry versus the refined 942-entry repository. It makes no LLM calls and is reproduced by
`runs/tsc_backend_overhead/scripts/run_all.sh`.

A fourth and fifth experiment study cross-client sharing on High School Geography:
`runs/tsc_collaboration/` compares Local-only vs entry-count-matched vs full shared repositories when
every client has seen the same construction questions, and `runs/tsc_collaboration_hetero/` repeats the
comparison with **complementary** coverage (each client keeps only 15 of the 60 construction questions).
Both use the same frozen corpus and question-level paired bootstrap; each has its own `run_all_*.sh`.

The matched-coverage experiment lives in `runs/tsc_collaboration/` (V.C of the TSC revision): a controlled
**cross-client sharing comparison** on High School Geography — Local-only vs entry-count-matched
Shared vs Shared-full — evaluated on 55 unseen questions with a question-level paired bootstrap.
It reuses the same frozen corpus and adds 2,200 new answers; run `runs/tsc_collaboration/scripts/run_all_tsc.sh`
to rebuild its figure, table and LaTeX from the shipped predictions (no API needed).

Plus two supporting analyses that were used during development and are kept for completeness:

| Item | Purpose | Where |
|---|---|---|
| **modeled upload time** (`D/R`) | the analytical baseline that Fig. 6 is cross-checked against | `p7/expevo_lifecycle/scripts/p9_modeled_upload.py` |
| **emulated upload** (tc/netns) | 1,200 real HTTP uploads over a shaped link, 5 rates × 5 trials | `p9/` (code) + `p9/results/full_20261027_194400/` (data) |

## 3. Backend refinement (V-D)

Four BM25 similarity thresholds are applied **independently to the same frozen full snapshot**
(never chained). Groups whose combined text exceeds the 3,500-word condensation budget are **not
merged**; their members are retained individually, which is why storage is non-monotonic at τ=40.

| Setting | Storage (MB) | Indexed entries | Storage ↓ | Entry ↓ | Accuracy (%) |
|---|---:|---:|---:|---:|---:|
| Full | 4.970 | 24,000 | 0.0 % | 0.0 % | 75.68 |
| BM25 100 | 4.099 | 20,624 | 17.5 % | 14.1 % | 75.50 |
| BM25 80 | 2.937 | 15,406 | 40.9 % | 35.8 % | 75.14 |
| BM25 60 | 1.599 | 8,332 | 67.8 % | 65.3 % | 74.41 |
| BM25 40 | 1.509 | 6,529 | 69.6 % | 72.8 % | 75.27 |

Accuracy is a macro average over four subjects, each with 55 held-out questions × 10 samples
(15 original + 40 extended), 2,200 answers per setting. All paired 95 % bootstrap intervals of the
accuracy difference include zero.

`runs/p10_backend_refinement/eval/` holds every sampled answer (`predictions.jsonl`,
`predictions_extended.jsonl`) with the retrieved experience ids, scores and prompt hashes, plus the
frozen extended held-out set (`heldout_extended.jsonl` + manifest).

## 4. Reproducing from scratch (optional, costs money)

The shipped data is enough for every table and figure. To rebuild the **experience corpus** itself you
need an API key and ~26 minutes of LLM time (~$0.5 at the time of the run):

```bash
cd p7/expevo_lifecycle
cp .env.example .env      # fill in LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
python -m src.prepare_mmlu     --config config/full100.yaml
python -m src.run_interactions --config config/full100.yaml   # 24,000 inference calls
python -m src.distill          --config config/full100.yaml   # 24,000 distillation calls
python -m src.route_and_store  --config config/full100.yaml
python -m src.refine           --config config/full100.yaml   # condensation at 4 thresholds
```

The refinement stage is deterministic given the snapshots and would overwrite the shipped repositories;
back them up first if you want to compare.

Re-running the **held-out evaluation** (3,000 + 8,000 calls) needs the API as well:

```bash
cd p7/expevo_lifecycle/runs/p10_backend_refinement
python scripts/evaluate_heldout.py --samples 10 --top-k 5 --temperature 0.7 --max-tokens 320
python scripts/evaluate_heldout.py --question-set extended --samples 10 --top-k 5 \
       --temperature 0.7 --max-tokens 320
```

Re-running the **network emulation** needs a Linux host with `CAP_NET_ADMIN`, `iproute2`, `iperf3` and
`tc`; the analysis and the figure only need the shipped CSVs:

```bash
cd p9 && python3 analyze.py --dir results/full_20261027_194400
```

## 6. Honesty notes

- Backend refinement happens **after** upload; it is never counted as an uplink saving.
- `G_ret` is the number of indexed experiences — a repository-size proxy, **not** measured BM25 latency.
- Fig. 6 is a **trace-driven discrete-event simulation** of a shared FIFO link: measured payloads,
  synthetic Poisson arrivals. It is not a wireless MAC/PHY simulation and not a field measurement.
- The `p9/` emulation is a Linux `tc`-shaped veth measurement, also not a field deployment.
- Accuracy differences across refinement thresholds are not statistically distinguishable at
  55 questions per subject; the paper should not claim a best threshold.
- No API keys are included. `.env.example` shows the variables; `.env` is git-ignored.
